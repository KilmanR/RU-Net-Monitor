🏷️ 1. Название проекта
Варианты: NetBench-RU, LinkPulse, SpeedTrace, RU-Net-Monitor
Рекомендация: netbench-ru (нейтрально, понятно, легко искать в Git)
Действие: Выбрать название, создать репозиторий, установить origin.

️ 2. Структура файлов

netbench-ru/

📝 4. Наполнение кода (Этап 1: Яндекс.Такси)
config.yaml: целевой хост, эндпоинты, кол-во повторов, таймауты
src/core.py: асинхронный замерщик с подробными docstring и inline-комментариями
src/services/yandex_go.py: специфичная логика (если нужна) или просто конфиг-запись
src/reporters.py: таблица в консоли через rich, сохранение в CSV
Каждый файл содержит:
Блок """ ... """ с назначением модуля
Type hints (def measure(...) -> dict:)
Комментарии # NOTE:, # TODO:, # HACK: где уместно
Обёртки try/except с логированием, а не print()
🧪 5. Тестирование и отладка
Запуск с --verbose флагом: вывод сырых таймингов (DNS, TCP, TLS, TTFB)
Проверка на разных сетях (Wi-Fi / 4G / раздача)
Имитация обрыва сети → скрипт не падает, пишет в лог и продолжает
python -m pytest tests/ → минимум 2 теста (успешный замер, таймаут)
Фиксация рабочей версии: git tag v0.1-yandex
➕ 6. Добавление следующего сервиса
Копирование template.py → telegram.py (или другой сервис)
Правка config.yaml: добавление секции с эндпоинтами и типом замера
Адаптация под специфику (например, для Telegram важен только пинг до api.telegram.org, для GitHub — скорость загрузки репозитория)
Коммит: git commit -m "feat: add telegram benchmark"
🎨 7. Корректировка вывода результатов
Переход на единую схему метрик: ping_avg, jitter, ttfb, download_mbps, status
Цветовая индикация: <50мс, 🟡 50–150мс, 🔴 >150мс
Экспорт в CSV с колонками: timestamp, service, metric, value, unit, network_type
Опция --export json/csv и --quiet (только итоговая строка)
Коммит: git commit -m "refactor: unify output format & add export"
🔁 8. Цикл развития (пункты 6 ↔ 7)
Новый сервис → адаптация метрик → правка отчёта → тесты → тег версии
Каждые 3 сервиса → рефакторинг core.py (оптимизация пулов соединений, кэширование DNS)
Вести CHANGELOG.md с описанием изменений и известных ограничений
💡 Рекомендации от меня (Best Practices)

Конфигурация
Все цели, таймауты, пороги вынести в config.yaml
Не трогать код при добавлении сервисов
Надёжность
httpx.Client(limits=..., timeout=...) + 2 повторных попытки с экспоненциальной задержкой
Сети нестабильны, скрипт не должен падать из-за одного дропа
Точность
Использовать time.perf_counter_ns() и усреднять по 3–5 замерам
Убрать шум от планировщика ОС и фоновых процессов
Безопасность
Не логировать полные URL с токенами, маскировать IP в отчётах
Защита от утечек при шаринге логов
Совместимость
Проверка на Python 3.10+, отсутствие хардкода путей
Запуск на ноутбуке, Raspberry Pi, VPS без правок
Версионирование
Семантические теги: v0.1.0-yandex, v0.2.0-telegram
Чёткая история, возможность отката
